# 面试题生成 SOP

> 本文档记录从需求分析到题目生成、导入、质量审查的完整流程，用于后续快速复现。

---

## 一、流程概览

```
需求分析 → 方向确定 → 题目设计 → 答案编写 → 导入数据库 → 质量审查
```

**核心原则**：
- 系统性：覆盖技术栈的完整知识体系
- 实用性：贴合真实面试场景
- 可复用：标准化流程，快速迭代

---

## 二、详细步骤

### 步骤 1：需求分析

**目标**：找出题库的薄弱环节和缺失方向。

**操作方法**：

1. **统计现有题库分布**
   ```bash
   # 查询各分类的题目数量
   npx tsx prisma/analyze-questions.ts
   ```

2. **识别薄弱模块**
   - 题目数量 < 10 的分类
   - 手写题占比 < 25% 的方向
   - 完全缺失的技术方向

3. **分析面试趋势**
   - 当前热门技术（微前端、低代码、Serverless）
   - 高频手写题（Promise、深拷贝、bind/call/apply）
   - 新兴方向（Rust 工具链、Monorepo）

**输出**：需要补充的方向清单

---

### 步骤 2：方向确定

**目标**：与用户确认补充方向，避免盲目生成。

**操作方法**：

1. **提供选项**（以可选择的方式询问用户）
   ```
   需要补充的方向：
   □ 算法与数据结构（现有 5 题，占比 0.4%）
   □ TypeScript 进阶（现有 13 题，占比 1.0%）
   □ 前端安全（现有 13 题，占比 1.0%）
   □ HTML/CSS 基础（现有 12 题，占比 0.9%）
   □ 更多手写题（当前占比 23%，目标 25%+）
   □ Node.js/全栈（现有 8 题，占比 0.6%）
   ```

2. **确认题目数量**
   - 每个方向建议 15-20 题
   - 手写题优先（提升 code 类型占比）

3. **确认难度分布**
   - easy: 20%
   - medium: 60%
   - hard: 20%

**输出**：确认的补充方向清单

---

### 步骤 3：题目设计

**目标**：按方向设计题目，确保覆盖核心知识点。

**操作方法**：

1. **创建题目文件结构**
   ```
   prisma/data/frontend-supplement{N}/
   ├── 01-{direction}.ts      # 第一个方向
   ├── 02-{direction}.ts      # 第二个方向
   ├── index.ts               # 统一导出
   └── types.ts               # 类型定义（如需要）
   ```

2. **题目设计原则**
   - **覆盖面**：每个方向覆盖 80% 核心知识点
   - **梯度**：easy → medium → hard 递进
   - **实用性**：优先高频面试题
   - **差异化**：避免与现有题目重复

3. **题型分配**
   | 方向 | 手写题 (code) | 问答题 (qa) |
   |------|---------------|-------------|
   | 算法 | 100% | 0% |
   | TypeScript | 30% | 70% |
   | 安全 | 0% | 100% |
   | HTML/CSS | 0% | 100% |
   | 手写强化 | 100% | 0% |
   | Node.js | 0% | 100% |

**输出**：题目文件（含 title、content、solution）

---

### 步骤 4：答案编写

**目标**：为每道题编写详细、准确的答案。

**答案质量标准**：

1. **代码题 (code)**
   - ✅ 完整可运行的代码
   - ✅ 关键逻辑注释
   - ✅ 使用示例
   - ✅ 复杂度分析（算法题）
   - ✅ 多种实现方式（如适用）

2. **问答题 (qa)**
   - ✅ 核心概念解释
   - ✅ 代码示例
   - ✅ 对比表格（如适用）
   - ✅ 最佳实践
   - ✅ 注意事项

**答案模板**：

```markdown
**核心概念**：一句话解释

**详细说明**：
1. 原理/机制
2. 使用场景
3. 代码示例

**最佳实践**：
- 建议 1
- 建议 2

**注意事项**：
- 注意点 1
- 注意点 2
```

**输出**：完整的题目文件（含高质量答案）

---

### 步骤 5：导入数据库

**目标**：将题目导入数据库，确保分类正确。

**操作方法**：

1. **创建导入脚本**
   ```typescript
   // prisma/import-frontend-supplement{N}.ts
   const NEW_CATEGORIES = [
     {
       id: "topic-前端-{方向}",
       name: "{方向名称}",
       type: "topic",
       description: "{描述}",
       parentId: null,  // 注意：避免外键错误
       sortOrder: 100,
     },
     // ... 更多分类
   ];
   ```

2. **执行导入**
   ```bash
   npx tsx --env-file=.env prisma/import-frontend-supplement{N}.ts
   ```

3. **验证导入结果**
   ```bash
   # 创建验证脚本
   npx tsx --env-file=.env prisma/verify-supplement{N}.ts
   ```

**常见问题**：
- `parentId` 外键错误 → 设置为 `null`
- 分类不存在导致题目跳过 → 检查 `NEW_CATEGORIES` 是否完整
- `DATABASE_URL` 未设置 → 添加 `--env-file=.env`

**输出**：导入成功的题目数据

---

### 步骤 6：质量审查

**目标**：检查题目质量，修复问题。

**审查清单**：

| 检查项 | 标准 | 工具/方法 |
|--------|------|-----------|
| 代码正确性 | 无语法错误，可运行 | 手动审查 + 运行测试 |
| 答案完整性 | 无截断，内容完整 | 读取文件检查 |
| 分类准确性 | 题目归类正确 | 对照分类树 |
| 难度合理性 | 符合标注难度 | 人工评估 |
| 重复度 | 无重复题目 | 搜索 title 关键词 |
| 标签完整性 | tags 字段完整 | 检查每个题目 |

**修复流程**：
1. 发现问题 → 记录问题清单
2. 修复代码 bug → 直接编辑文件
3. 调整分类 → 修改 `categoryId`
4. 重新导入 → 执行导入脚本

**输出**：质量审查报告

## 三、实战案例

### 案例：补充 6 个方向（98 题）

**背景**：用户要求补充前端面试题的薄弱环节。

**执行过程**：

1. **需求分析**
   - 算法与数据结构：5 题 (0.4%) → 需补充
   - TypeScript：13 题 (1.0%) → 需补充
   - 前端安全：13 题 (1.0%) → 需补充
   - HTML/CSS：12 题 (0.9%) → 需补充
   - 手写题占比：23% → 需提升至 25%+
   - Node.js：8 题 (0.6%) → 需补充

2. **题目设计**
   ```
   01-algorithm.ts        → 15 题（排序、查找、树、图、链表）
   02-typescript-advanced.ts → 15 题（泛型、工具类型、装饰器）
   03-security.ts         → 15 题（XSS、CSRF、CSP、JWT）
   04-html-css.ts         → 20 题（语义化、盒模型、Flexbox、Grid）
   05-handwrite-more.ts   → 20 题（Promise、bind/call/apply、设计模式）
   06-nodejs.ts           → 13 题（Event Loop、Stream、Express/Koa）
   ```

3. **导入结果**
   - 新增分类：15 个
   - 新增题目：98 题
   - 手写题占比：23% → 24%

4. **质量审查**
   - 发现 bug：bind 实现中变量名错误（已修复）
   - 分类优化：部分 CSS 题目分类需调整
   - 综合评分：⭐⭐⭐⭐

## 四、常用命令

```bash
# 分析现有题库
npx tsx prisma/analyze-questions.ts

# 导入题目
npx tsx --env-file=.env prisma/import-frontend-supplement{N}.ts

# 验证导入结果
npx tsx --env-file=.env prisma/verify-supplement{N}.ts

# 查询特定分类的题目数
npx tsx -e "
import { PrismaClient } from '@prisma/client';
const prisma = new PrismaClient();
const stats = await prisma.category.groupBy({
  by: ['id', 'name'],
  _count: { questions: true },
  orderBy: { _count: { questions: 'asc' } }
});
console.log(stats);
"
```

## 五、注意事项

1. **分类 ID 规范**
   - 格式：`topic-前端-{方向}`
   - 避免使用不存在的 `parentId`
   - 新增分类必须在 `NEW_CATEGORIES` 中声明

2. **题目格式规范**
   - `title`：简洁明确
   - `content`：题目描述
   - `solution`：Markdown 格式答案
   - `difficulty`：easy/medium/hard
   - `questionType`：code/qa
   - `categoryId`：必须存在
   - `tags`：数组，3-5 个标签
   - `jobRole`：frontend

3. **代码题注意事项**
   - 使用 `myXxx` 命名避免覆盖原生方法
   - 包含边界条件处理
   - 添加使用示例

4. **问答题注意事项**
   - 避免纯理论，必须有代码示例
   - 使用表格对比增强可读性
   - 包含最佳实践和注意事项
